# Review after steps 3–4 (2026-10-20)

What could go wrong or be better, by how much it matters, and when to fix it.

Marks:
- **Very critical**: wrong results or a broken game today. Fix now.
- **Critical**: becomes a real bug or a wrong conclusion in a coming step. Fix before that step.
- **Worth doing**: makes a coming step easier or better.
- **Nitpick**: only here because you asked for everything.

Nothing is very critical or critical now: the rules are checked against `ataxx`, the tests pass, and the two critical points are settled (see the end).

## Worth doing

1. **A time limit makes tournaments noisy.** Several games at once heat the laptop and slow it down, so an agent with a time limit searches less deeply in one run than in another, and the same seed no longer gives the same games.
   *When:* step 9. Compare Deepening agents at a fixed depth in tournaments, and use the time limit in the window.

2. **The engine does extra work that a search will feel.** `play` checks the move again, and `ends_game` scans the board three times per move. A search knows its moves are legal.
   *When:* step 9, after the profiler confirms it. A `play` without the check, and pawn counts kept in `Position`.

3. **A heavy agent may make the window stutter.** The agent thread and the drawing share one Python interpreter (the GIL).
   *When:* check in step 7. If it shows, run the agent in its own process in the window.

## Nitpick

4. `pyproject.toml` lists the packages by hand. A new folder like `schlurp/heuristics/` would not install until it is added there. Fix when we add a folder.
5. An agent error closes the window with a traceback. Right while we write agents; a message in the window would be kinder. Any time.
6. No `ruff`, no CI. A few lines are over 120 characters. A GitHub Actions job running `pytest` would catch a broken push. Any time.
7. `Move.parse` takes only lower case (`C3` is an error). Matters only for a text mode or the web version.

## Settled

- **Two threads could use the same agent at once** (was critical). Now one lock per agent and a stop flag: see `docs/adr/0004`.
- **500 games cannot see small differences** (was critical). 500 games give ±4.4%, and trying many heuristic weights in step 8 will find some winners by luck. Agreed: where a difference is too small to see, we play more games, and we replay the best version with a new seed before we believe it.
- **Greedy before Watch.** Swapped in the plan, so the thoughts panel has real scores to show.
- How a game ended was guessed from the pawn counts in the window: now `Result.ended_by`.
- The start menu reads its agents from `AGENTS` (step 5).
- Tournaments use half the CPU cores by default, print their seed, and name an agent that plays an illegal move.
