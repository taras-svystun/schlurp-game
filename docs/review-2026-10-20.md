# Review after steps 3–4 (2026-10-20)

What could go wrong or be better, by how much it matters, and when to fix it.

Marks:
- **Very critical**: wrong results or a broken game today. Fix now.
- **Critical**: becomes a real bug or a wrong conclusion in a coming step. Fix before that step.
- **Worth doing**: makes a coming step easier or better.
- **Nitpick**: only here because you asked for everything.

Nothing is very critical today: the rules are checked against `ataxx`, and the tests pass.

## Critical

1. **Two threads can use the same agent at once, and forgotten threads keep running.**
   Undo forgets the thinking agent's thread, but Python cannot stop a thread. The next turn starts a new thread with the same agent object while the old one may still run.
   *Why it matters:* harmless with Random (it answers at once). An AlphaBeta or MCTS agent keeps data between moves (a table of positions, a tree), and two threads would change it at the same time. The old search also keeps the CPU busy and slows the new one. Hint (step 6) adds one more user of an agent.
   *When:* before step 7. Add a `stop` flag that a search checks, or give each thread a fresh agent.

2. **500 games cannot see small differences, and trying many versions finds winners by luck.**
   500 games give A's points ±4.4%. Our own 40-game run called Random stronger than itself (see `docs/agents/random.md`).
   *Why it matters:* in step 8 heuristic weights may differ by 1–3%, and we will try many of them. Some will look better by luck alone, and we would keep the wrong weights.
   *When:* step 8. Play the best version again with a new seed, use more games, or a test that stops as soon as one agent is clearly ahead (SPRT, as chess engines do).

## Worth doing

3. **Greedy before Watch.** Watch (step 5) is mostly the thoughts panel: move scores and the expected line. Random has no thoughts, so the panel would be built on empty data.
   *When:* decide now, before step 5. Swapping is cheap; Hint can stay with Greedy.

4. **A time limit makes tournaments noisy.** Several games at once heat the laptop and slow it down, so an agent with a time limit searches less deeply in one run than in another, and the same seed no longer gives the same games.
   *When:* step 9. Compare Deepening agents at a fixed depth in tournaments, and use the time limit in the window.

5. **The engine does extra work that a search will feel.** `play` checks the move again, and `ends_game` scans the board three times per move. A search knows its moves are legal.
   *When:* step 9, after the profiler confirms it. A `play` without the check, and pawn counts kept in `Position`.

6. **A heavy agent may make the window stutter.** The agent thread and the drawing share one Python interpreter (the GIL).
   *When:* check in step 7. If it shows, run the agent in its own process in the window.

## Nitpick

7. `pyproject.toml` lists the packages by hand. A new folder like `schlurp/heuristics/` would not install until it is added there. Fix when we add a folder.
8. The start menu keeps its own list of agents (`MENU_AGENTS`) next to `AGENTS`. Fix in step 6, when Greedy is added to both.
9. An agent error closes the window with a traceback. Right while we write agents; a message in the window would be kinder. Any time.
10. No `ruff`, no CI. A few lines are over 120 characters. A GitHub Actions job running `pytest` would catch a broken push. Any time.
11. `Move.parse` takes only lower case (`C3` is an error). Matters only for a text mode or the web version.
